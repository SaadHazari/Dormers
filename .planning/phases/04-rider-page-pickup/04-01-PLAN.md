**File 1: `src/contexts/ops/usecases/get-dorm-counts.ts`**

Create a use-case that returns per-dorm meal counts for the rider. Mirror the `getKitchenCounts` pattern exactly — same parallel fetch of `subscriptions` + `customers`, same filters (5DAYS Saturday skip, skipped_dates, paused_dates), but group by `customers.dorm_name` instead of summing veg/non-veg.

The function signature:
```typescript
export type DormCountsRecord = Record<string, number>

export async function getDormCounts(
  todayIso: string,
  dayName: string,
  isSaturday: boolean,
): Promise<DormCountsRecord>
```

Implementation details:
- Import `createAdminSupabaseClient` from `@/infra/supabase/admin-client`
- Parallel fetch: `subscriptions` table (select `id, customer_id, week_type, skipped_dates, paused_dates`, filter `.in('status', ['Active', 'Paused', 'Skipped'])`) and `customers` table (select `id, dorm_name`)
- Build a `customerMap: Map<string, string | null>` mapping customer id to dorm_name
- Loop over subscriptions applying these filters in order:
  1. `if (sub.week_type === '5DAYS' && isSaturday) continue`
  2. `if ((sub.skipped_dates ?? []).includes(todayIso)) continue`
  3. `if ((sub.paused_dates ?? []).includes(todayIso)) continue`
- Look up customer's `dorm_name` from customerMap. If null or missing, skip (no dorm = no delivery stop)
- Increment count for that dorm_name in the result object
- Return `Record<string, number>` (NOT a Map — this will be passed as RSC prop directly)
- Note: we do NOT need `isVegOnDayName` here — the rider carries all boxes (veg + non-veg) to the same dorm. Each active subscription = 1 box regardless of preference.
- Note: `customers.dorm_name` stores exact strings matching `DORM_SHAPE_MAP` keys: `'The Myriad'`, `'KSK Homes'`, `'Yugo'`, `'DSOA Residence'`, `'Study World'`. The use-case does NOT import or reference `DORM_SHAPE_MAP` — it returns raw dorm names. The UI layer handles mapping.

**File 2: `src/app/ops/[token]/actions.ts`**

Create a server action for pickup confirmation. The directory `src/app/ops/[token]/` does not exist yet — create it.

```typescript
'use server'

import { createAdminSupabaseClient } from '@/infra/supabase/admin-client'

export async function confirmPickup(
  dormName: string,
  expectedCount: number,
  opsTokenId: string,
  deliveryDateIso: string,
): Promise<{ ok: boolean; error?: string }> {
  const sb = createAdminSupabaseClient()

  const { error } = await sb.from('delivery_events').upsert(
    {
      delivery_date: deliveryDateIso,
      dorm_name: dormName,
      trip_number: 1,
      expected_count: expectedCount,
      ops_token_id: opsTokenId,
      confirmed_at: new Date().toISOString(),
      verified: false,
    },
    { onConflict: 'delivery_date,dorm_name,trip_number' },
  )

  if (error) return { ok: false, error: error.message }
  return { ok: true }
}
```

Key decisions:
- `upsert` with `onConflict: 'delivery_date,dorm_name,trip_number'` makes re-tap idempotent (no unique constraint error)
- `trip_number: 1` is hardcoded (single trip per day for now)
- `verified: false` — Phase 5 will set this to true after photo verification
- `deliveryDateIso` is passed FROM the RSC (UAE wall time) — never computed inside the action (Node.js runs in UTC)
- `confirmed_at` uses `new Date().toISOString()` — this is the server timestamp of when the rider tapped confirm, NOT a delivery date

  ```
  const AE_OFFSET_MS = 4 * 60 * 60 * 1000
  const aeNow = new Date(Date.now() + AE_OFFSET_MS)
  const aeDow = aeNow.getUTCDay()
  const isSunday = aeDow === 0
  const isSaturday = aeDow === 6
  const todayIso = aeNow.toISOString().slice(0, 10)
  const DAYS_OF_WEEK = ['Sunday','Monday','Tuesday','Wednesday','Thursday','Friday','Saturday']
  const dayName = DAYS_OF_WEEK[isSunday ? 1 : aeDow]
  ```
