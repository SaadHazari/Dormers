Create `src/lib/dorm-wars/coupon-synth.ts` containing the exact code from RESEARCH Pattern 2 (lines 230-289 of 07-RESEARCH.md).

**Key implementation points (do NOT deviate):**
- Order of operations: credit first (capped at plan total), THEN tier % applied to remainder. Formula: `discount = credit + floor((amount - credit) * tier_pct / 100)`. This avoids Pitfall #4.
- If `discountFils <= 0`, return `{ couponId: null, ... }` early — do NOT call Stripe with a zero-amount coupon (Stripe rejects).
- Coupon `name` field: `` `Dorm Wars rewards (${creditAppliedFils/100} AED credit + ${tierPercent}% tier)` `` per RESEARCH line 272. Prefix dorm-wars coupons with `dw-` style is unnecessary because Stripe's `name` is descriptive, not unique.
- **Add `redeem_by` per Pitfall #1:** `redeem_by: Math.floor(Date.now()/1000) + 86400`. RESEARCH Pattern 2 example does NOT include this, but Decision #1 (line 650) explicitly requires it. Use the Decision #1 form.
- Metadata MUST include `applied_credit_ids: appliedCreditIds.join(',')` so the webhook can look them up. Stripe metadata values are strings — always coerce with `String(...)`.
